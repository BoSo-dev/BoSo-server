# BoSo 팀 전체 구현 계획

## 서비스 목표와 공통 세팅

기획안의 세 가지 핵심 기능은 교통 정책 간편 요약, 개인별 정책 변경 To-Do, 정책 정보를 근거로 답변하는 챗봇이다. 회원·개인 조건과 서비스 내 알림은 이 흐름을 지원한다. 두 팀원은 공통 기반을 공유하고 각 기능 브랜치에서 업무 로직을 구현한다.

`chore/project-setup`에는 실행 환경, 전체 도메인의 빈 라우터와 API 연결, DB 세션·마이그레이션 환경, 오류 처리, 테스트·CI·Docker, 공통 작업 지침을 포함한다. 도메인 테이블·업무 API·외부 AI 호출은 후속 기능에서 구현한다.

설치 버전은 `uv.lock`, 실행 명령은 README, 모듈 경계는 [architecture.md](architecture.md), 검증 명령은 `scripts/check.py`가 기준이다. `/health/ready`는 현재 DB 연결만 확인하며 도메인 스키마 준비 여부를 보장하지 않는다.

## 기능별 목표와 의존 관계

| 영역 | 구현 목표 | 선행 기능 | 완료 기준 |
| --- | --- | --- | --- |
| DB 연동 | Supabase 연결·SSL·마이그레이션·RLS 기준 | 공통 세팅 | PostgreSQL 검증과 실제 Supabase 연결 여부를 구분해 기록 |
| 회원 | 이메일 가입·로그인·토큰 갱신·로그아웃 | DB 기반 | 중복·오인증·만료·갱신·폐기·접근 제어 검증 |
| 내 정보 | 지역·생년월일·교통카드·주 이용 수단 | 회원 | 본인 조건 저장·조회와 입력 검증 |
| 정책 데이터 | 정책·변경 버전·출처·대상 조건·필요 행동 관리 | DB 기반 | 검수 이력·게시 버전 보존·반영 중복 및 오류 처리 검증 |
| 정책 조회 | 목록·카테고리·검색·상세·변경 전후·관련성 | 정책 데이터, 개인화에는 내 정보 | 화면에 필요한 정보와 공식 출처·대상 여부 제공 |
| To-Do | 조건 판정·할 일 생성·상태별 목록·체크·마감일 | 회원·내 정보·정책 | 중복 방지·재계산·완료 이력·마감 경계 검증 |
| 챗봇 | Gemini 정책 상담·대화 저장·근거·할 일 연결 | 회원·내 정보·정책, 할 일 연결에는 To-Do | 근거 없는 답변·정보 부족·외부 장애 처리 검증 |
| 알림 | 새 할 일·마감 임박·목록·미읽음·읽음 처리 | 회원·To-Do | 알림 중복 방지·소유자 검증·스케줄러 재실행 검증 |

이 표는 팀 전체 기능 계획이며 특정 팀원의 담당표가 아니다. 담당자·진행 순서·세부 구현 방식은 이슈·작업 문서·PR에서 관리한다. 현재 회원·정책 담당 작업의 별도 맥락은 [작업 문서](workstreams/member-policy.md)에 있다.

## 공동 개발 순서

1. 공통 세팅을 검토·통합한 뒤 같은 실행·검증 환경을 사용한다.
2. DB 연동 기반 위에서 회원과 정책 데이터를 나누어 구현하고 제공할 모델·스키마를 문서화한다.
3. 내 정보·정책 조회를 연결한 뒤 To-Do와 챗봇을 병렬 구현한다. 챗봇의 관련 할 일 연결은 To-Do 계약이 준비되면 추가한다.
4. 할 일 생성·마감 기준으로 알림을 연결하고 프론트엔드와 전체 사용자 흐름을 검증한다.
5. 운영용 환경변수·마이그레이션·백업·상태 확인·배포 절차를 검증한다.

공통 파일과 migration 충돌 처리, 선행 PR을 base로 하는 방법은 [브랜치 규칙](branch-strategy.md)을 따른다. 각 기능은 코드·테스트·마이그레이션·API 설명을 같은 PR에 포함한다.

## 연동·데이터·검증 기준

- 업무 API는 `/api/v1` 아래에 두고 Pydantic/OpenAPI로 실제 요청·응답을 공유한다. 공통 오류는 `code`, `message`, `details`, `request_id`다.
- 회원 인증은 현재 이메일·비밀번호와 애플리케이션 JWT, 데이터 저장소는 Supabase PostgreSQL을 기준으로 계획한다. 인증 구현을 바꾸면 관련 모듈의 의존성을 함께 갱신한다.
- 정책 버전과 적용 조건을 To-Do·챗봇이 함께 참조한다. 정책 출처·검수일·적용 기간을 보존하며 화면의 예시 날짜를 운영 정보로 간주하지 않는다.
- 외부 AI는 검수된 정책을 바탕으로 설명하며 개인화 대상·마감일을 임의로 결정하지 않는다. 외부 장애와 근거 부족을 구분한다.
- 새 환경 실행, 회원 인증, 프로필 저장, 정책 확인, 할 일 진행, 근거 있는 상담, 알림 확인까지 통합 검증한다.
- 실제 PostgreSQL·Supabase·AI·배포 검증과 로컬 대역 테스트를 구분한다. 자격 증명이 없으면 미검증 범위와 실행 방법을 보고한다.
