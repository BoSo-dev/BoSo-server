# BoSo 구현 계획

## 확정된 담당 범위

사용자가 제공한 기획안·화면·담당 기능 목록을 기준으로 다음 기능을 구현한다.

- 이메일 회원가입·로그인·토큰 갱신·로그아웃·내 정보 관리.
- 교통 정책 목록 조회 API와 상세 조회 API.
- 공식 출처를 검수한 정책 데이터 등록·수정·보관.
- Supabase PostgreSQL 정책·회원 DB 연동.

관리자 기능은 제외한다. 정책 데이터 관리는 서버 운영자가 검수 파일을 가져오는 CLI로 수행한다. To-Do·챗봇·알림은 최초 전체 기획에 존재하지만 현재 담당 구현 범위에는 포함하지 않는다.

## 현재 단계: 프로젝트 세팅

`chore/project-setup`은 실행 가능한 FastAPI 기반, DB 세션·마이그레이션 환경, 오류 형식, 테스트, CI, Docker, 에이전트 작업 규칙과 커밋·PR 스킬만 포함한다. 회원·정책 테이블과 기능 API는 아직 구현하지 않는다.

설치 버전은 `uv.lock`, 실행 명령은 README, 검증 명령은 `scripts/check.py`를 기준으로 한다. `/health/ready`는 현재 DB 연결만 확인하며 도메인 스키마 준비 여부를 보장하지 않는다.

## 후속 기능과 완료 기준

| 브랜치 | 변경 내용 | 완료 기준 |
| --- | --- | --- |
| `feat/supabase-db` | 연결 설정, SSL, 마이그레이션·RLS 운영 기준 | 실제 Supabase 연결 검증 또는 자격 증명 부재를 구분해 보고 |
| `feat/auth` | 회원 테이블, 비밀번호 해시, JWT·갱신 세션, 내 정보 | 가입·중복·로그인·만료·갱신·폐기·다른 사용자 접근 테스트 통과 |
| `feat/policy-data` | 정책·버전 모델, 공식 출처·검수일, JSON 가져오기·보관 CLI | 재실행 중복 방지, 잘못된 입력 전체 rollback, 게시 버전 보존 |
| `feat/policy-api` | 목록·검색·카테고리·페이지네이션·상세 | 활성 정책만 노출, 없는 ID 404, 변경 전후·출처 제공 |

목록·상세 조회는 공개 API로 두고 인증된 사용자 프로필과 별개로 제공한다. API prefix는 `/api/v1`이다. 필드와 오류·경계 조건은 각 기능 브랜치에서 OpenAPI 및 테스트와 함께 구체화한다.

회원은 애플리케이션의 이메일·비밀번호와 JWT로 인증하고 Supabase는 PostgreSQL 저장소로 사용한다. Supabase Auth로의 변경은 별도 설계 변경이다.

## 데이터 정확성과 검증

- 화면의 날짜·정책 변경 예시는 운영 사실로 간주하지 않는다.
- 실제 데이터에는 공식 URL·검수일·적용 기간을 저장한다. 시연 데이터는 명확히 표시한다.
- PostgreSQL 통합 검증과 로컬 SQLite 단위 검증을 구분한다.
- 인증정보가 없으면 실제 Supabase 프로젝트를 만들거나 임의 연결하지 않고 설정·마이그레이션·연결 확인 방법을 완성한다.
- 운영 배포·도메인 설정·원격 PR 게시 여부는 작업 요청에 맞춰 별도로 수행한다.
