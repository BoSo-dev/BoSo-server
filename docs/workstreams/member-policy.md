# 회원·정책 담당 작업 계획

이 문서는 현재 사용자가 맡은 작업의 맥락이다. 팀 전체 기능 범위나 다른 팀원의 구현 방식을 제한하는 공통 지침이 아니다. 전체 구조는 [architecture.md](../architecture.md), 팀 계획은 [implementation-plan.md](../implementation-plan.md)를 따른다.

## 현재 담당 항목

- 이메일 회원가입·로그인·토큰 갱신·로그아웃·내 정보 관리.
- 교통 정책 목록·카테고리·검색·상세 조회.
- 공식 출처·검수일·적용 기간·변경 버전을 포함한 정책 데이터 등록·관리.
- Supabase PostgreSQL 연결·마이그레이션·접근 기준 검증.

현재 이 작업에서는 관리자 API·권한·화면을 만들지 않고 검수 파일을 가져오는 CLI로 정책 데이터를 관리할 예정이다. 이는 이 작업의 구현 계획이며 팀 공통 구조에 관리자 기능 추가 금지나 CLI 사용 의무를 부여하지 않는다.

## 작업 단위

| 브랜치 | 주요 산출물 |
| --- | --- |
| `feat/supabase-db` | 접속 설정·SSL·마이그레이션·연결 검증 |
| `feat/auth` | 회원 모델·인증 API·갱신 세션·접근 제어 |
| `feat/user-profile` | 개인화 조건·보유 교통카드의 저장·조회 |
| `feat/policy-data` | 정책 모델·검수 데이터 가져오기·보관 |
| `feat/policy-api` | 목록·상세·변경 전후·공식 출처 조회 |

## 다른 기능에 제공할 정보

- To-Do·챗봇·알림이 사용할 인증 사용자 식별자와 내 정보 계약.
- To-Do·챗봇이 참조할 정책 버전·대상 조건·필요 행동·공식 URL.
- 프론트엔드가 사용할 실제 OpenAPI 요청·응답과 오류 형식.

공통 계약의 변경은 관련 모듈에 미치는 영향과 함께 PR에 기록한다. 개인 작업 범위가 바뀌면 이 문서를 갱신하며 루트 `AGENTS.md`에 다른 모듈을 제한하는 규칙을 추가하지 않는다.
